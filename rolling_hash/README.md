# Introduction
This is a learning project. The goal is to build the **SIMPLEST**, algebra-based hash algorithm that exhibits perfect statistical properties.

# Definitions
- `BITS` is a power of two, at least `128`, and specifies the width (in bits) of the internal state of the **Polynomial Hash** function.
- `MODULUS` is the largest **safe prime** less than `2^BITS`.
- `BASE` is uniformly sampled from the primitive roots modulo `MODULUS`, except the least one.
- `INCREMENT` and `SEED` are independently and uniformly sampled integers from (half-open) interval `[1, MODULUS)`.

# Algorithm
Let us go step by step:

0) Classic polynomial hash used in the **Rabin–Karp algorithm**:

```python
def poly_hash(binary: bytes) -> int:
    result: int = 0
    for byte in binary:
        result = (result * BASE + byte) % MODULUS
    return result
```

**Problem**: `hash('') == hash('\0') == hash('\0' * 2) == hash('\0' * 3) == hash('\0' * 3) == ...`

1) **Bijective** numeration (like column numeration in **Excel**):

```python
def poly_hash(binary: bytes) -> int:
    result: int = 0
    for byte in binary:
        result = (result * BASE + byte + 1) % MODULUS
    return result
```

**Problem**: Incrementing the rightmost byte of the `binary` just increments the hash value (if no overflow occurs).

2) Same as **Bijective**, but length of the input is appended. The `chain` function in the code is `itertools.chain`.

```python
def poly_hash(binary: bytes) -> int:
    result: int = 0
    for byte in chain(binary, (len(binary),)):
        result = (result * BASE + byte + 1) % MODULUS
    return result
```

**Problem**: For short inputs with small byte values, the state may remain below `MODULUS`, making modular reduction ineffective and leaving high-order bits unused. In particular, the empty input always hashes to `1`, regardless of `BASE`.

3) **LCG**-style (**Linear Congruential Generator**):

```python
def poly_hash(binary: bytes) -> int:
    result: int = SEED
    for byte in chain(binary, (len(binary),)):
        result = (result * BASE + byte + INCREMENT) % MODULUS
    return result
```

**Problems**:
- If you have a collision for two (different) strings, you would (very likely) not have the collision for the `BASE` changed. But changing `INCREMENT` or `SEED` does not impact collisions.
- **LCG** does not pass the **NIST Statistical Test Suite** due to its linearity.
- The 64-bit hash must depend on every bit of the internal state; simply taking the least significant 64 bits ignores the rest. Finalization must mix all state bits into the 64-bit result.

4) Finalizator:
```python
@final
@dataclass(frozen=True, kw_only=True, slots=True)
class Finalizer:
    degree: ClassVar[Final[int]] = 3

    multiplier: int
    increment: int
    modulus: Modulus

    @final
    def __call__(self, state: int, /) -> int:
        remainder: int = state % self.modulus
        result: int = (
            pow(remainder, Finalizer.degree, mod=self.modulus.modulus)
            * self.multiplier + self.increment
        ) % self.modulus
        div, mod = divmod(result << self.modulus.bits, self.modulus.modulus)
        return div + (mod > remainder)
```

# Evaluation

Let us consider two test sequences, where each element of a test sequence is a binary-string (`bytes` in **Python**):
- **base-256 bijective numeration system**: `[b"", b"\x00", b"\x01", b"\x02", ..., b"\xFF", b"\x00\x00", b"\x00\x01", b"\x00\x02", ..., b"\xFF\xFF", b"\x00\x00\x00", ...]`.
- **Gray code**: `[b"\x00", b"\x01", b"\x03", b"\x02", b"\x06", b"\x07", b"\x05", b"\x04", b"\x0C", b"\x0D", b"\x0F", b"\x0E", b"\x0A", b"\x0B", b"\x09", b"\x08", b"\x18", ...]`.

Each test sequence is generated by mapping counter values `(0, 1, 2, 3, 4, ...)` to their corresponding binary-string representations. Each generated binary-string is processed by the hash function to output a **64-bit integer**. Concatenating the sequence of hash function values produces **bit stream**. The resulting **bit stream** must successfully pass the entire **NIST SP 800-22** statistical test suite.

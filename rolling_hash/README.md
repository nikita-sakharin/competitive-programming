# Introduction
This is a learning project. The goal is to build the **SIMPLEST**, algebra-based hash algorithm that exhibits perfect statistical properties. 

To evaluate the algorithm's statistical quality, the hash function is tested in a counter-mode using a **base-256 bijective numeration system**. Each element of the test sequence is byte string (`bytes` in **Python**). The sequence is generated by mapping counter values (0, 1, 2, 3, 4, ...) to their corresponding bijective byte representations: `[b"", b"\x00", b"\x01", b"\x02", ..., b"\xFF", b"\x00\x00", b"\x00\x01", b"\x00\x02", ..., b"\xFF\xFF", b"\x00\x00\x00", ...]`

Each generated byte string is processed by the hash function to output a **64-bit integer**. The resulting sequence of hash values (bit stream) must successfully pass the entire **NIST SP 800-22** statistical test suite.

# Definitions
- `BITS` is the size (in bits) of the internal state of the **Polynomial Hash** function.
- `MODULUS` is the largest **safe prime** less than `2^BITS`.
- `BASE` is randomly generated primitive root modulo `MODULUS`.
- `INCREMENT` and `SEED` are random integers in the (half-open) interval `[0, MODULUS)`.

# Algorithm
Let us go step by step:
0) **Classic** version from the author of the algorithm (**Rabin-Karp**):

```python
def poly_hash(binary: bytes) -> int:
    result: int = 0
    for byte in binary:
        result = (result * BASE + byte) % MODULUS
    return result
```

Problem: `hash('') == hash('0') == hash('0' * 2) == hash('0' * 3) == hash('0' * 3) == ...`

1) **Bijective** numeration (like column numeration in **Excel**):

```python
def poly_hash(binary: bytes) -> int:
    result: int = 0
    for byte in binary:
        result = (result * BASE + byte + 1) % MODULUS
    return result
```

Problem: Adding 1 to the rightmost symbol (byte) of the string just increments the hash value.

2) Same as **Bijective**, but length of the input is appended. The `chain` function in the code is `itertools.chain`.

```python
def poly_hash(binary: bytes) -> int:
    result: int = 0
    for byte in chain(binary, (len(binary),)):
        result = (result * BASE + byte + 1) % MODULUS
    return result
```

Problem: Assume bits is `128` (or even `256`), then the algorithm underutilizes the width of the internal state, as it could grow bit slowly. It would be better if appending of each symbol (byte) forced the internal state to be taken by `MODULUS`. So, statistical properties should be enhanced for high-position bits of the state.

3) LCG-style (**Linear Congruential Generator**):

```python
def poly_hash(binary: bytes) -> int:
    result: int = SEED
    for byte in chain(binary, (len(binary),)):
        result = (result * BASE + byte + INCREMENT) % MODULUS
    return result
```

Problems:
- If you have a collision for two (different) strings, you would (very likely) not have the collision for the `BASE` changed. But changing `INCREMENT` or `SEED` does not impact collisions.
- **LCG** does not pass the **NIST Statistical Test Suite** due to its linearity.
- If the hash function is intended to generate fewer bits than the width of the internal state, a finalization step must be done, rather than simply taking the corresponding number of least significant bits.

3) Finalizator:
**Cubic Congruential Generator**

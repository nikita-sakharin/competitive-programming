# Introduction
This is a learning project. The goal is to build the **simplest**, algebra-based **non-cryptographic hash function** with cryptographic-grade statistical properties.

# Definitions
- `BITS` is a power of two, at least `128`, and specifies the width (in bits) of the internal state of the **polynomial hash** function.
- `MODULUS` is the largest **safe prime** less than `2^BITS`.
- `BASE` is uniformly sampled from the primitive roots modulo `MODULUS`, except the least one.
- `INCREMENT` and `SEED` are independently and uniformly sampled integers from (half-open) interval `[1, MODULUS)`.

# Algorithm
Let us go step by step.

## Classic
The classic **polynomial hash** used in the **Rabin–Karp algorithm**:

```python
def poly_hash(binary: bytes) -> int:
    result: int = 0
    for byte in binary:
        result = (result * BASE + byte) % MODULUS
    return result
```

**Problem**:

Two null-byte strings of different length (including empty) collide to the same `0` hash.

`poly_hash(b"") == poly_hash(b"\0") == poly_hash(b"\0" * 2) == poly_hash(b"\0" * 3) == 0`

## Bijective
**Bijective** numeration (like column numeration in **Microsoft Excel**):

```python
def poly_hash(binary: bytes) -> int:
    result: int = 0
    for byte in binary:
        result = (result * BASE + byte + 1) % MODULUS
    return result
```

**Problem**:

Incrementing the rightmost `byte` of the `binary` just increments the hash value (if no overflow occurs). For almost all `BASE`s the equality holds:

`poly_hash(b"A") + 2 == poly_hash(b"B") + 1 == poly_hash(b"C")`

## Length-appended
Length of the input (`binary`) is appended (the `chain` function in the code is `itertools.chain`):

```python
def poly_hash(binary: bytes) -> int:
    result: int = 0
    for byte in chain(binary, (len(binary),)):
        result = (result * BASE + byte + 1) % MODULUS
    return result
```

**Problem**:

For short inputs with small byte values, the state may remain below `MODULUS`, making modular reduction ineffective and leaving high-order bits unused. In particular, the empty input always hashes to `1`, regardless of `BASE`:
- `poly_hash(b'') == 1`
- `poly_hash(b'\0') == BASE + 2`

## Linear Congruential Generator
3) **LCG**-style - `0` is replaced with `SEED` and `1` is replaced with `INCREMENT`:

```python
def poly_hash(binary: bytes) -> int:
    result: int = SEED
    for byte in chain(binary, (len(binary),)):
        result = (result * BASE + byte + INCREMENT) % MODULUS
    return result
```

**Problems**:
- If you have a collision for two (different) strings, you would (very likely) not have the collision for the `BASE` changed. But changing `INCREMENT` or `SEED` does not impact collisions.
- **LCG** does not pass the **NIST Statistical Test Suite** due to its linearity.
- The 64-bit hash must depend on every bit of the internal state; simply taking the least significant 64 bits ignores the rest. Finalization must mix all state bits into the 64-bit result.

## Finalization
```python
@final
@dataclass(frozen=True, kw_only=True, slots=True)
class Finalizer:
    degree: ClassVar[Final[int]] = 3

    multiplier: int
    increment: int
    modulus: Modulus

    @final
    def __call__(self, state: int, /) -> int:
        remainder: int = state % self.modulus
        result: int = (
            pow(remainder, Finalizer.degree, mod=self.modulus.modulus)
            * self.multiplier + self.increment
        ) % self.modulus
        div, mod = divmod(result << self.modulus.bits, self.modulus.modulus)
        return div + (mod > remainder)
```

При финализации возведение в куб происходит в поле internal state, не в финальном поле. Это важно, так как поле internal state по безопасному простому, а finalizer поле по обычному простому числу.

# Evaluation
Let us consider two test sequences, where each element of a test sequence is a binary-string (`bytes` in **Python**):
- **base-256 bijective numeration system**: `[b"", b"\x00", b"\x01", b"\x02", ..., b"\xFF", b"\x00\x00", b"\x00\x01", b"\x00\x02", ..., b"\xFF\xFF", b"\x00\x00\x00", ...]`.
- **Gray code**: `[b"\x00", b"\x01", b"\x03", b"\x02", b"\x06", b"\x07", b"\x05", b"\x04", b"\x0C", b"\x0D", b"\x0F", b"\x0E", b"\x0A", b"\x0B", b"\x09", b"\x08", b"\x18", ...]`.

Each test sequence is generated by mapping counter values `{0, 1, 2, 3, 4, ...}` to their corresponding binary-string representations. Each generated binary-string is processed by the hash function to output a **64-bit unsigned integer**. Concatenating the sequence of hash function values produces **bitstream**. The resulting **bitstream** must successfully pass two statistical test suites:
- **NIST SP 800-22**
- **TestU01**
